# 图注 — `architecture.svg` / `.pdf`

## 正式版

**图 1　方法总览。** 处理一道题的流程如下。先由程序准备上下文 (a)：取出目标数据库的全量 schema
与每表三行样本，不做检索、不附示例，数据库只读打开。上下文连同问题送入声明生成器，这是全流程
唯一的一次模型调用 (b)——提示词规定模型只能返回一个 JSON 对象，其中同时包含 SQL 与一张声明表，
并附上 11 条从训练集蒸馏的基准约定；声明表要求模型写明这条 SQL 隐含的判断：所设定的时间口径、
每个输出列的来源、派生值所依据的参照系，以及反事实前提。随后交给校验器 (c)，它不调用模型，只用规则
检查 SQL 与声明表是否自洽、所引用的表列与取值是否真实存在，其中四条核心校验恒开、两条可选校验
按需启用。若有校验不通过，其失败原因会作为一条消息追加进对话并要求模型重新生成，消息只指出哪一个
判断需要重做而不提供答案，重写最多两轮；图中示例即由此在第二轮补上了除以 `Capacity`，其余不变。
全部校验通过后，SQL 只读执行，结果与参考答案比对计分 (d)。在 Archer `en_dev` 上取得
VA 100.0、EX 63.46。

## 短版（版面紧张时）

**图 1** 程序先把全量 schema 与每表三行样本拼成上下文 (a)；随后是唯一的一次模型调用 (b)，模型须一次
给出 SQL 与一张声明表，写明这条 SQL 隐含的时间口径、输出列来源、取值参照系与反事实前提；校验器 (c)
用纯规则检查两者是否自洽、引用是否真实存在，不通过的校验会作为反馈要求模型重写，最多两轮；通过后
SQL 只读执行并与参考答案比对计分 (d)。Archer `en_dev`：VA 100.0、EX 63.46。
