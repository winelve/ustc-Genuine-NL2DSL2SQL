# C3 SQL 名称解析修复

## 目标

修复 DSL C3 接地检查对合法 SQL 名称的三类误报，同时继续拦截真正不存在的表和列：

1. 带 `"..."`、`` `...` ``、`[...]` 的物理列；
2. `FROM/JOIN` 中声明的物理表别名；
3. CTE 或子查询实际输出的派生列。

## 设计

C3 继续以 SQLite 物理 schema 为最终依据，但在比较前从已经解析的 SQL AST 构造
一个只读的名称解析环境：

- 标识符比较统一去除 SQLite 支持的外层引号并转为小写；
- 物理表别名只解析到 AST 中对应的真实物理表；
- CTE 和子查询按各自 `SELECT` 的实际输出列建立关系，引用必须能在对应关系中解析；
- 派生表达式中的无限定列仅在物理 schema 或当前 SQL 的可见派生输出中存在时通过。

不采用“看到别名就跳过 C3”或“任意 `AS` 名称全局有效”的宽松策略，避免掩盖拼错的
表、列以及作用域外引用。

## 测试

先添加失败测试，再实现：

- 双引号、反引号和方括号列能够解析到物理 schema；
- `f.column` 能通过 `FROM frpm AS f` 解析，未声明的别名仍报错；
- `cte.derived_column` 和合法的 CTE 派生列引用通过；
- CTE 未输出的列、作用域外别名、真实不存在的物理列继续报错；
- BIRD trace 中 question_id 0、3、8 的相应误报形成回归用例。

## 验收

- 新增测试先在旧实现上按预期失败；
- 定向 DSL/BIRD 测试通过；
- 日志案例不再产生上述三类误报；
- `.venv\Scripts\python.exe -m pytest -q` 全绿；
- 不修改生成/评测通信协议，不触碰数据库写权限。
