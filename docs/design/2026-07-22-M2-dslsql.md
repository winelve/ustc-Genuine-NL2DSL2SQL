# M2 设计：dslsql —— 半程 IR（声明层 DSL + 规则校验循环）

> 状态：设计已口头批准（2026-07-22 与用户商定），待用户审阅本文档。
> 在 M1 `plansql` pipeline 上增量修改（分支 `reproduction/OraPlan-SQL`）。
> M2 − M1 分差 = 本项目中心论据（DSL 中间层的价值）。

## 1. 定位决策：为什么是"半程 IR"而不是路线图原画的"全程 IR"

三个候选定位（2026-07-22 与用户讨论，选定方案二）：

| 方案 | 形态 | 弃/选理由 |
|---|---|---|
| ① 全程 IR | 模型只输出受限 DSL，sqlglot 编译成 SQL | 弃：表达力瓶颈风险高。M1 已证明"强推理骨干经过更窄的中间层"会掉分（自由文本 plan −9.6）；受限代数只会更窄，且须覆盖 gold 里的 UNION ALL/相关子查询/CTE |
| ② **半程 IR（选定）** | SQL 仍由模型全力直出，但必须随附结构化声明表；纯规则校验声明的完整性/与 SQL 的一致性/接地，不过则定向修复 | 保住 thinking 骨干 40.4 的底盘，零表达力天花板；DSL 的作用 = 强制显式化 + 给 M3 知识注入留插座 |
| ③ 片段 IR | 算式走 DSL 编译，骨架 SQL 直出，程序拼接 | 弃：拼接边界工程上切不干净 |

**错误分布依据**（最新一轮 +反事实原则、EX 40.4、VA 100%，62 道错题）：
剩余错误全部是"SQL 合法但语义错"。C 类主导模式是**时间回算**：

- ① 没意识到要算——"at the time of release" 被无视，直接 `SELECT Name, Age`
  （en_dev #0/#1/#4/#5/#12 同族）；
- ② 算了但口径错——`Age` 列的时间锚（Archer 口径：`Age` 为当前年龄，当前年 =
  `strftime('%Y','now')`）猜错（#2）。

纯结构校验（类型/列存在/值存在）对这两类**一条都抓不到**。因此 M2 的价值主张不是
"约束/校验器"，而是：

- 对①：schema 必填字段**强制表态**（把 H 类靠提示词原则修好的"强制注意力"手法机械化）；
- 对②：M2 只能逼模型把口径假设显式写进 anchor 槽位，**判对错要等 M3 公式库注入**——
  M2 先把插座装好。

**两项事实核查（2026-07-22，用户提出）**：

- **`commonsense_knowledge` 字段测试时不提供**：Archer 论文（2024.eacl-long.6）
  主实验（§6.1）只输入问题本身；"w/ knowledge"仅为 §6.2 的分析实验；OraPlan 全篇未用
  该字段。官方设定 = w/o knowledge。**约束：M3 公式库不得直接使用 dev 集该字段**，
  合法路线是从 train 集该字段离线蒸馏通用公式库，靠 train→dev 泛化。
- **数据库无字段注释**：10 库中仅 bike_1 的 DDL 带注释，dev 两库（concert_singer、
  world_1）零注释——模型对列语义的全部依据 = 列名 + 3 行样本。"`Age` 为当前年龄"
  这类口径在输入中根本不存在，只能靠模型猜或外部注入，佐证 M2 anchor 声明 +
  M3 知识注入的组合设计。

## 2. 在 pipeline 里的位置（单变量消融）

M1 的 planner（含反事实原则）与投票/执行淘汰**零改动**，唯一新变量 = 声明层 + 校验循环：

```
planner ──→ dslgen LLM：输出 {sql, declarations} JSON
                 ↓
             校验层（纯规则，无 LLM，四组检查）
                 ↓ 不通过：具体失败项拼进对话 → 重生成，≤2 轮（可调）
                 ↓ 通过或轮数用尽（取最后一版 SQL，绝不空串，trace 记"未通过"）
             执行淘汰 → 投票 → 预测文件
```

## 3. DSL 本体：声明表 schema（Pydantic，零 Archer 专属词汇）

```jsonc
{
  "sql": "SELECT ...",
  "declarations": {
    "time_context": {              // 必填——对准①的主武器，模型不能沉默跳过
      "displaced": true,           // 问的是"现在"还是别的时间点？
      "reference": "song release year (Song_release_year)"
    },
    "outputs": [                   // SQL 每个输出列必须声明，不许漏
      { "name": "Name", "source": "column", "column": "singer.Name" },
      { "name": "age",  "source": "derived",
        "expr": "Age + (Song_release_year - strftime('%Y','now'))",
        "anchors": { "Age": "now" } }   // 参与运算的每个时间语义列的时间锚
    ],
    "assumptions": [               // H 类反事实 → ASSUME 数据补丁（改数据，不是过滤）
      { "target": "singer.Song_release_year",
        "where": "Song_Name = 'Gentleman'", "value": "2001" }
    ]
  }
}
```

通用性约束：字段语义全部是领域无关的（时间上下文/输出来源/反事实补丁），
不含任何 Archer 题型关键词；不做问题文本的关键词触发（刷分路线，已否决）。

## 4. 校验器（纯规则，四组）

| # | 检查 | 内容 | 对准的病 |
|---|---|---|---|
| C1 | 完整性 | 必填字段齐全；sqlglot（sqlite 方言）解析 SQL：输出列与 `outputs` 一一对应，且声明 `derived` 的列真有算式、`column` 的真是裸列 | ① 强制表态 |
| C2 | 一致性 | `displaced=true` ⇒ 至少一个输出列 derived；有 `assumptions` ⇒ 假设值必须参与计算（改数据而非仅过滤） | ① 说到必须做到 |
| C3 | 接地 | 声明引用的表/列存在于 schema；字面值 difflib 近邻核对库内值（M3 值链接强化时再引 rapidfuzz） | 幻觉（当前 VA 100，保险） |
| C4 | 锚完整 | `derived` 表达式中每个时间语义列必须有 anchor | ② 逼出口径假设（M3 插座） |

**可行性已验证**（2026-07-22，脚本见 scratchpad）：sqlglot 30.13.0 解析
en/zh train+dev 全部 1036 条 gold + 104 条 plansql-pro-thinking 预测 SQL，
**零失败**；AST 可区分裸列（Column）与派生表达式（如 Sub），C2 所需能力成立。

## 5. 修复循环与 trace

- 校验失败 → 失败项以具体文字（如"输出列 age 声明为 derived 但 SQL 中是裸列"）
  作为 user 消息拼进同一对话重新生成，默认 ≤2 轮（类属性，可调）。
- trace 每题记录：各检查触发情况、修复轮数、最终通过与否、每轮的 SQL 与声明。
  触发率/修复率即论文里声明层的过程证据。
- 兜底与 M1 相同：轮数用尽取最后一版 SQL；JSON 解析彻底失败按框架约定记空串。

## 6. 结构与命名

- 注册名 **`dslsql-pro`**（骨干同 plansql-pro：deepseek-v4-pro + thinking），
  预测文件 `predictions/dslsql-pro_<数据集>.json`。
- 新增：`model/pipeline/dsl.py`（Pydantic schema + 四组校验器，纯函数）、
  `stages/declare.py`（dslgen 调用 + 修复循环编排）、
  `prompts/dslgen.system.md` / `dslgen.user.md`。
- planner 相关文件与 M1 注册项零改动；`PlanSQL` 编排接新 stage 即成 `DSLSQL` 子类。

## 7. 测试策略

- 校验器纯函数单测：好/坏声明各若干（漏声明、声明与 SQL 不一致、幻觉列、缺 anchor）。
- 端到端假 LLM：先吐坏声明再吐好声明，验证修复循环走通；CI 不打真 API。
- 照旧 `pytest -q` 全绿才提交。

## 8. 已知边界（诚实预期）

- M2 **修不了**口径本身错（C4 只逼假设显式化，判对错是 M3 公式库的事）。
- `time_context.displaced` 填错（模型坚持"没有时间位移"）时校验器无从纠正——
  机制与 H 类提示词原则同源：强制表态本身即干预手段，残余风险接受。
- 修复轮数上限 2、注册名 `dslsql-pro` 为默认拍板项，用户可改。
